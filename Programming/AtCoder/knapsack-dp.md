# 0/1ナップサック問題と貪欲法

## 概要

「予算や容量に上限があり、その中で価値（満足度など）の合計を最大化する」問題では、単純な貪欲法では正解できないことがある。

### 貪欲法の例

価値が高い順に並べて、

    sort(vec.rbegin(), vec.rend());

のように「今いちばん価値が高いものを、入るなら取る」としても、全体として最適になるとは限らない。

例えば予算10で、

| 値段 | 価値 |
|---:|---:|
| 6 | 100 |
| 5 | 99 |
| 5 | 99 |

の場合、価値100を先に取ると合計100だが、99+99=198のほうが大きい。

## 0/1ナップサックDP

各品物を「選ぶ / 選ばない」の2択として考える。

`dp[money]` を「現在までに考えた品物を使って、予算money以内で得られる最大価値」とする。

新しい品物の値段を `price`、価値を `value` とすると、

- 選ばない: `dp[money]`
- 選ぶ: `dp[money - price] + value`

なので、

    dp[money] = max(dp[money], dp[money - price] + value);

となる。

### 重要：予算を大きい方から回す

    for (int money = limit; money >= price; money--) {
        dp[money] = max(dp[money], dp[money - price] + value);
    }

0/1ナップサックでは、同じ品物を1回しか選べない。

予算を小さい方から更新すると、今更新した `dp` を同じ品物の計算で再利用してしまい、1つの商品を複数回選んだ状態になり得る。

そのため、**0/1ナップサックでは容量・予算を降順に更新する**。

## 問題を見たときの判断

次のような条件が見えたら、ナップサックDPを疑う。

- 選ぶ / 選ばないの2択
- 各アイテムは基本的に1回しか使えない
- 容量・予算などに上限がある
- 合計の価値を最大化 / 最小化する

逆に「価値が高い順」「コスパが高い順」などの単純な貪欲法を使う場合は、**その選び方が必ず最適になる理由を説明できるか**を考える。

## 今回の学び

「コードを書けるか」だけではなく、**最初にどのアルゴリズムが必要なのかを見抜くことが重要**。

今回のように貪欲法でTC1だけ通る場合は、

> 「実装が間違っている」のではなく、「局所的に良い選択を積み重ねても全体最適にならない問題なのでは？」

と疑う。
